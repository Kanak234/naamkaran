पहले यह पढ़ो — नाम अभी तय नहीं है
──────────────────────────────────

  "SŪTRA" नाम काम नहीं करेगा. जाँच में पता चला कि वो पहले से लिया हुआ है,
  और ठीक उसी क्षेत्र में:

    Emma Leonhart की "Sutra" — एक typed, purely functional भाषा जिसका
    compiled forward pass एक PyTorch neural network है.
    arXiv 2605.20919, GitHub, और अपनी website.
    उनका extension भी .su है, और उनका नाम भी पाणिनि वाले सूत्र से आया है.

    इसके अलावा हिंदी में लिखी जाने वाली एक और भाषा भी "Sutra" नाम की है.

  इसलिए इस औज़ार में कोई नाम जमा हुआ नहीं है. जो भी नाम तुम तय करो,
  वो --naya-naam से दे दो.

  अभी default "nirukta" रखा है — निरुक्त, छह वेदांगों में से एक, यास्क
  का लिखा हुआ, जिसका काम है शब्दों की व्युत्पत्ति और सही अर्थ निकालना.
  एक compiler ठीक यही करता है. programming language के तौर पर यह नाम
  खोजने पर कहीं नहीं मिला — पर तुम ख़ुद भी जाँच लो.


नाम पक्का करने से पहले — पाँच जाँचें
──────────────────────────────────────

  यह सूची इसलिए बनी क्योंकि पहली बार यह जाँच नहीं की गई थी.

    १. web search:  "<नाम>" programming language
    २. arXiv पर वही खोज — नई भाषाएँ पहले वहाँ आती हैं,
       GitHub पर मशहूर होने से बहुत पहले
    ३. GitHub search
    ४. ipindia.gov.in — Class 9 और Class 42, Search Type "Contains"
    ५. domain, npm, crates.io — नाम खाली है या नहीं

  पाँचों साफ़ हों, तभी नाम पक्का करो.


चलाना कैसे है
─────────────

  क़दम १ — पहले देखो, बदलो मत

      python3 tools/naamkaran.py ~/klions --naya-naam nirukta

      कुछ नहीं बदलेगा. गिनती देखो — 13 crates हैं तो नाम भी 13 बदलने चाहिए.

  क़दम २ — नक़ल बनाकर बदलो

      python3 tools/naamkaran.py ~/klions --karo --nakal ~/nirukta \
          --naya-naam nirukta

      असली folder छुआ भी नहीं जाएगा. कुछ बिगड़ा तो पुराना जस का तस पड़ा है.
      आख़िर में औज़ार ख़ुद ढूँढेगा कि कहीं 'klions' बचा तो नहीं.

  क़दम ३ — बनाकर देखो

      cd ~/nirukta && cargo build && cargo test

      179 tests पास दिखें, तभी मानना कि नामकरण हुआ. एक भी कम — कुछ छूटा है.

  पूरे विकल्प:

      --naya-naam         नया नाम              (default: nirukta)
      --naya-ext          लंबा extension        (default: नाम जैसा)
      --naya-ext-chhota   छोटा extension        (default: nir)
      --naya-binary       compiler का binary    (default: नाम + c)
      --poori-suchi       सारी बदली files दिखाओ


औज़ार आठ शक्लें अलग-अलग सँभालता है
────────────────────────────────────

  एक sed से यह काम नहीं होता, क्योंकि 'klions' आठ शक्लों में छिपा है:

      klionsc        compiler का binary
      libklions      बनी हुई library
      KLIONS_HOME    environment variable
      .klions / .kl  file extension
      klions-lexer   crate का नाम
      klions_ir      library का नाम
      KlionsError    Rust का type
      KLIONS         docs और strings में

  क्रम मायने रखता है — सबसे लंबा और ख़ास पहले, सबसे आम सबसे बाद में.
  उल्टा क्रम कुछ को ठीक करेगा और कुछ को चुपचाप तोड़ देगा.

  '.kl' सबसे नाज़ुक है क्योंकि बहुत छोटा है. वो सिर्फ़ तब बदलता है जब
  सचमुच extension की जगह हो — 'klass.klx' और 'file.klang' नहीं छुए जाते.

  "जाँच लो" वाली सूची पर ध्यान देना. उसमें वो बदलाव होते हैं जो अंदाज़े
  पर हुए — जैसे quote में अकेला "kl". लगभग हमेशा वो extension ही होता
  है, पर आँख से देख लेना.


मंडल भंडार — compiler का incremental cache
──────────────────────────────────────────

  चार परतें, इस हिसाब से कि चीज़ कितनी तेज़ी से बासी होती है:

      बिंदु    keywords, builtin types, prelude
               compiler का version बदले तभी बदलता है
               कभी अपने आप नहीं मिटता

      वलय-१    बाहरी packages का विश्लेषण
               एक बार बना, महीनों चला — और सबसे महँगा यही होता है
               कभी अपने आप नहीं मिटता

      वलय-२    तुम्हारे अपने modules का IR, types, borrowck
               90 दिन

      वलय-३    इसी बार की चीज़ें — फैलाए हुए macro, अस्थायी IR
               3 दिन

  cargo की तरह सब एक जगह क्यों नहीं:
      क्योंकि तब 'cargo clean' ही अकेला रास्ता बचता है, और वो सब कुछ
      फेंक देता है — वो महँगा dependency विश्लेषण भी जो बीस मिनट में
      बना था और जिसमें कोई गड़बड़ थी ही नहीं.

  दो नियम पूरे भंडार को चलाते हैं:

      १. निर्भरता कुंजी में घुसती है.
         इसलिए file बदलते ही कुंजी बदल जाती है और पुराना अपने आप बेकार
         हो जाता है. cache invalidation अलग से करनी ही नहीं पड़ती —
         वो कुंजी बनने के तरीक़े से अपने आप होती है.

      २. जो बार-बार काम आया वो अंदर चढ़ता है.
         वलय-३ की कोई चीज़ पाँच बार काम आई, तो वो अस्थायी नहीं रही —
         वलय-२ में चढ़ जाती है, जहाँ 3 दिन के बजाय 90 दिन बचेगी.

         फ़ायदा यह कि तुम्हें पहले से तय नहीं करना पड़ता कि क्या ज़रूरी
         है. इस्तेमाल ख़ुद बता देता है.

  mandala/mandala_bhandar.py Python में है और compiler Rust में —
  इसलिए वो चलने वाला code नहीं, ढाँचे का नमूना है. Folder की शक्ल,
  कुंजी बनाने का तरीक़ा, उम्र और चढ़ने के नियम — सब वहाँ तय हैं और
  जाँचे हुए हैं. Rust में उतारना सीधा है.
